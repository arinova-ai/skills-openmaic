# Deep Interactive learning design

Default to **doing**, not reading. An explanatory segment earns its place only
when it makes the next manipulation possible or consolidates what the learner
has already observed.

## Structure

- Open once: frame the question and name what the learner is about to
  manipulate. Do not begin with definitions or a table of contents.
- Make the body hands-on. Each activity isolates one mechanism, variable, or
  structure so the learner can change it and observe the result.
- Close with a diagnostic or short explanation that makes the learner state
  what the manipulation established and transfer it to a changed case.
- Vary the modality as the concept moves from “watch it” to “trace it” to
  “predict it.” Repeating the same interaction format without a learning reason
  is a design failure.

## Choose an activity format

| Format | Use when the learner should… |
| --- | --- |
| simulation | vary parameters and watch a system respond |
| explorable diagram | follow structure, flow, or hierarchy |
| code experiment | read, modify, and run a short program that embodies the idea |
| rule-bound game | make repeated decisions and see consequences accumulate |
| spatial model | inspect an object or process from several viewpoints |

If the conversation cannot provide the intended medium, do not claim that it
exists. Offer the same mechanism inline using a small table, successive states,
pseudocode, an ASCII diagram, or a turn-by-turn decision exercise, and say what
the learner should change and observe.

## Write a complete activity brief

Every hands-on activity states:

- the one concept or mechanism under inspection;
- the controls, choices, or inputs the learner can vary;
- the initial prediction the learner must make;
- the observable result and what counts as evidence;
- the misconception or boundary case the activity exposes;
- the question that turns observation into an explanation;
- the handoff to the next activity.

For a simulation, name the actual variables. For a diagram, name the nodes and
relationships. For code, name the language and the behavior to change. For a
game, state the rule, decision, feedback, and win condition. For a spatial
model, state the objects, viewpoints, and inspections.

## Conversation workflow

1. Settle the learner, outcome, available time, and mechanism to explore.
2. Propose the full activity sequence and wait for explicit approval.
3. Develop each approved activity in order, keeping one mechanism per activity.
4. Ask for a prediction before revealing a result or explanation.
5. After each manipulation, require the learner to name the observation and
   the conclusion it supports.
6. End with a changed condition that tests whether the learner can transfer the
   mechanism rather than repeat wording.

## Naming

Titles name what the learner does or discovers.

- Good: 「拖动倾角，看射程怎么变」「顺着数据流走一遍」「猜下一步会发生什么」
- Bad: 「抛体运动」「数据流概述」「知识点回顾」

## Completion check

- Hands-on work is the clear majority of the lesson.
- Each activity has a populated brief and only one load-bearing mechanism.
- Consecutive activities vary modality or justify why repetition is necessary.
- Learners predict, manipulate, observe, explain, and transfer.
- No result is revealed before the learner has a chance to inspect it.
- Any unavailable medium has an honest inline fallback.
